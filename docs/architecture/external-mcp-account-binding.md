# 外部 MCP 工具账户绑定与授权

状态：已被纠正，仅保留为历史讨论

更新日期：2026-08-15

> 本文把 CloudMCP 错误地作为 LLMWEB 用户需要理解和绑定的产品对象，不再作为实施依据。当前权威设计是 [用户训练 API 与内部连接器](user-api-and-internal-connectors.md)：LLMWEB 向每个注册用户提供通用账户级 API，CloudMCP 与 GitOps 仅作为内部连接器消费该正式能力。

## 1. 目标

LLMWEB 允许用户把 CloudMCP 等外部 MCP 工具连接到自己的训练工作台，并授权它代为完成项目、算力和训练操作。外部工具必须代表一个已经注册并主动授权的真实用户操作，不能使用内部虚拟用户、独立工作区或管理员暗绑路径绕过 LLMWEB 治理面。

用户完成绑定后，网页操作与外部 MCP 操作必须进入同一个用户工作区，遵守同一套项目配额、Runner 归属、训练规则和数据边界。用户能够在 LLMWEB 中看见连接、理解它能做什么、查看最近操作并随时撤销。

## 2. 核心决策

- 外部 MCP 是用户授权的操作客户端，不是另一类 LLMWEB 用户或管理员。
- 绑定只能由已登录的 LLMWEB 用户主动批准；不得通过配置邮箱、工作区 ID 或内部账号建立业务绑定。
- 第一版一个绑定对应一个 Passport 用户及其唯一 LLMWEB 工作区。
- CloudMCP 平台身份与用户授权身份必须分别验证，缺少任意一层都不得调用用户业务能力。
- CloudMCP 不得提交用户 ID、邮箱、工作区或配额作为可信身份；LLMWEB 根据不可伪造的绑定凭证在服务端解析真实用户。
- 网页与外部 MCP 只在身份入口和参数适配上不同，必须复用同一套应用服务和领域规则。
- GitOps 节点只能使用绑定账户工作区生成的一次性配对码加入训练池。
- 用户撤销绑定只终止外部工具访问，不删除项目、Runner、数据、训练记录或模型，也不默认取消正在执行的训练。
- 第一版一个 LLMWEB 账户只保留一个有效 CloudMCP 绑定；重新绑定必须明确替换并撤销旧凭证。
- 现有内部 CloudMCP 工作区完成显式迁移和验收后必须硬退役，不保留隐式回退。

## 3. 用户体验

### 3.1 设置入口

登录后的工作台增加“设置”入口。设置页包含“外部 MCP 工具”区域，每个外部工具使用一张审批卡片表达用户需要完成的动作，不展示 Provider Bridge、请求头、scope 字符串或工作区 ID 等实现细节。

未连接时，CloudMCP 卡片展示：

- 工具名称与可信来源。
- 一句话说明：它可以代用户管理 LLMWEB 中的项目、算力连接和训练任务。
- 将获得的用户能力：查看工作台状态、创建项目、连接算力、准备数据、启动训练、读取结果。
- 明确排除：不能删除项目、数据和模型；不能静默转移算力；不能获得用户密码或原始训练数据。
- 主动作“连接 CloudMCP”。

连接审批时，页面必须明确显示当前登录账户，并说明批准后的实际影响。用户确认后才创建绑定。

已连接时，卡片展示：

- “已连接”状态。
- 绑定的当前账户。
- 最近使用时间。
- 最近操作的简要入口。
- “解除连接”动作。

用户看到的统一表达是“由 CloudMCP 代你执行”，不能把外部操作伪装成用户亲自点击，也不能显示成无法识别的内部用户。

### 3.2 高影响动作

绑定默认允许 CloudMCP 启动训练。以下动作不能仅凭基础绑定静默执行：

- 取消正在运行的训练。
- 解除或转移 Runner。
- 删除项目、数据、训练记录或模型产物。
- 改变账户或工作区归属。

第一版不向外部 MCP 授予删除能力。取消训练必须携带该次动作的明确确认依据；Runner 转移继续走独立的解除与重新连接流程。

### 3.3 撤销

用户解除连接后：

- 绑定立即失效，CloudMCP 不能再读取或修改该工作区。
- 已经领取并执行的训练默认继续，用户可在网页单独取消。
- 用户仍可在网页访问全部项目、Runner、训练记录和模型。
- 再次连接创建新绑定和新凭证，旧凭证永不恢复。

## 4. 身份与授权模型

### 4.1 双层认证

每次外部调用必须通过两层验证：

1. **平台认证**：证明请求来自 LLMWEB 已批准的 CloudMCP Provider。
2. **账户授权**：证明该请求代表一个仍然有效的用户绑定。

平台 Bridge 凭证不能替代账户授权。账户绑定凭证也不能绕过平台来源验证。

推荐授权流程：

```text
CloudMCP 请求连接
        ↓
用户进入 LLMWEB 并完成登录
        ↓
设置页展示 CloudMCP 审批卡片
        ↓
用户确认授权
        ↓
LLMWEB 签发短时、一次性授权码
        ↓
CloudMCP 交换访问凭证
        ↓
LLMWEB 保存可撤销的账户绑定
```

不得向 CloudMCP 交付 Passport 密码、LLMWEB Session Cookie、网页到控制面的内部信任令牌或可伪造用户身份的请求头。

### 4.2 绑定凭证

- 一次性授权码必须短时有效、只能使用一次，并绑定目标 Provider 和当前用户。
- 访问凭证应短期有效；长期访问使用可轮换、可撤销的刷新凭证。
- LLMWEB 只保存凭证摘要，不保存可直接使用的明文凭证。
- 凭证轮换不得改变用户工作区或对象归属。
- 撤销、账户停用、Provider 停用或绑定被替换后，刷新与访问都必须失败。

### 4.3 内部权限

第一版面向用户保持一个统一授权心智，内部按稳定能力限制调用：

```text
workspace:read
project:write
runner:pair
training:write
artifact:read
```

内部权限用于服务端最小授权和审计，不要求普通用户逐项理解技术 scope。若未来某项权限会直接改变用户责任、成本、风险或结果，再升级为用户可选项。

## 5. 统一业务路径

认证完成后，网页和外部 MCP 都必须调用同一套应用服务：

```text
网页会话身份 ───────┐
                   ▼
              统一应用服务
                   ▲
外部绑定身份 ───────┘
```

统一应用服务负责：

- 创建和读取工作区、项目。
- 从 Passport 获取当前权益并执行项目配额。
- 生成 Runner 一次性配对码并校验工作区归属。
- 创建和检查数据集。
- 创建训练实验及版本化任务。
- 选择 checkpoint。
- 暂停、继续和经明确确认的取消。
- 汇总训练状态、指标与模型产物。

Provider Bridge 不得复制一套业务规则，也不得通过构造网页内部请求头模拟用户。它只负责验证外部身份、解析绑定、校验授权能力并调用统一应用服务。

Passport catalog 与 access decision 仍是权益真相。任何会增加资源或创建对象的外部操作都必须按目标账户的当前权益重新判断；CloudMCP 不得声明或长期缓存项目配额。权益不可确认时拒绝新增，但不删除或隐藏已有对象。

## 6. CloudMCP、GitOps 与 Runner 的关系

绑定后的正式链路为：

```text
真实注册用户
  │ 在 LLMWEB 设置页批准
  ▼
CloudMCP 账户绑定
  │
  ├── LLMWEB Provider Bridge
  │      └── 用户工作区中的项目、数据、训练和结果
  │
  └── GitOps 治理工具
         └── 指定节点安装或升级 Runner
                  │
                  └── 使用该用户工作区生成的一次性配对码注册
```

CloudMCP 不直接向 Runner 下发训练命令。LLMWEB 控制面为绑定用户创建结构化任务，Runner 使用自己的设备凭证主动领取所属工作区的任务。GitOps 负责节点准备、安装和升级，不成为第二套训练业务入口。

已有 Runner 属于其他工作区时必须拒绝静默覆盖。环境缓存可以按既有发行协议复用，Runner 身份、数据、checkpoint、模型产物和业务日志不得跨账户复用。

## 7. 数据模型

账户绑定至少保存：

```text
ExternalMcpBinding
- id
- provider_id
- passport_user_id
- workspace_id
- status
- granted_capabilities
- credential_hash / refresh_credential_hash
- created_at
- approved_at
- last_used_at
- revoked_at
- replaced_by_id
```

外部操作审计至少保存：

```text
ExternalMcpAuditEvent
- id
- binding_id
- workspace_id
- actor_user_id
- provider_id
- action
- target_type
- target_id
- outcome
- occurred_at
- safe_request_summary
```

审计记录不得保存 Secret、一次性授权码、完整访问凭证、用户密码、原始训练数据或本地绝对路径。

一个账户第一版最多有一个有效 CloudMCP 绑定。数据库约束必须阻止并发审批产生多个有效绑定；替换操作应在同一事务中撤销旧绑定并建立新绑定。

## 8. 接口边界

需要提供四类正式接口，具体路径可在实现时遵守仓库路由风格，但语义不得改变：

1. **读取连接状态**：供设置页读取当前账户的 CloudMCP 绑定与最近使用时间。
2. **创建审批**：在已登录会话中创建短时一次性授权码。
3. **交换凭证**：CloudMCP 使用授权码交换绑定凭证，同时验证平台身份。
4. **撤销绑定**：由已登录用户撤销当前绑定并使全部关联凭证失效。

Provider Bridge 的每次业务请求都必须包含平台身份与账户绑定凭证。服务端解析绑定后才能调用工具；不得接受请求参数中的用户、邮箱、工作区或配额覆盖解析结果。

## 9. 现有内部路径迁移

当前 `cloudmcp-operator` 与 `ws_cloudmcp_operator` 只作为待退役历史来源，不再作为目标设计的一部分。现有 Runner、项目、数据集、实验、任务、事件和模型记录必须作为一个关联集合处理。

正式迁移顺序：

1. 用户指定并登录接收历史对象的真实注册账户。
2. 确认该账户完成 CloudMCP 绑定。
3. 确认内部工作区没有运行中、租约中或等待用户选择的任务。
4. 生成只读迁移预览，列出 Runner、项目、数据集、实验、任务、事件和产物引用的精确数量与目标工作区。
5. 在单个数据库事务中迁移所有关联对象的工作区归属，保留对象 ID、Runner 设备身份、指标、checkpoint 和产物引用。
6. 从普通网页入口验证目标账户能看到并继续操作全部对象。
7. 从 CloudMCP 绑定入口验证读取与新增操作落入同一工作区并遵守真实配额。
8. 验证旧内部工作区无法再读取或修改迁移对象。
9. 删除代码中的内部身份构造和内部工作区配置入口；未提供有效账户绑定时必须明确拒绝，不能回退。

迁移不得新建第二个 Runner 冒充归属转移，不得只迁移 Runner 而遗留项目或训练历史，也不得删除节点上的用户数据和模型产物。

## 10. 发布与回退

实施应分为可验证阶段，但生产启用必须保持单一正式入口：

1. 建立绑定数据模型、统一应用服务和审计能力。
2. 完成设置页审批卡片与授权交换。
3. 让 Provider Bridge 强制要求有效账户绑定。
4. 在隔离环境验证网页和 CloudMCP 操作进入同一工作区。
5. 预览并执行现有内部工作区迁移。
6. 验收后硬退役内部身份路径。

发布期间不得让相同外部调用同时写入内部工作区和真实用户工作区。回退只允许恢复到发布前完整版本与数据归属；内部身份路径一旦完成迁移并正式退役，不得作为日常故障兜底重新启用。

## 11. 验收标准

只有同时满足以下条件，直连路径退役才算完成：

- 未登录用户不能批准绑定。
- 用户能在设置页看见、批准和撤销 CloudMCP。
- CloudMCP 只凭平台 Bridge 凭证不能读取任何用户工作区。
- CloudMCP 不能通过提交用户 ID、邮箱、工作区或配额切换身份。
- 网页与 CloudMCP 创建的对象出现在同一工作区和同一项目列表中。
- 两种入口对项目配额、Runner 归属、训练参数和任务状态执行相同规则。
- GitOps 节点使用绑定账户生成的配对码加入该账户训练池。
- 用户能看见“由 CloudMCP 代你执行”的最近操作记录。
- 撤销后所有 CloudMCP 读写立即失败，网页操作与已领取训练不受破坏。
- 替换绑定后旧凭证不能恢复使用。
- 现有内部工作区关联对象完整迁移，目标账户可以查看历史指标和模型产物。
- 代码、配置、数据库和正式工具中不再存在 `cloudmcp-operator` 或 `ws_cloudmcp_operator` 业务回退。
- 普通用户界面不暴露 Bridge、Header、scope、Runner 内部身份或 GitOps 实现细节。

## 12. 不在本轮设计范围

- 一个 CloudMCP 连接同时切换多个 LLMWEB 账户。
- 团队成员角色与细粒度项目共享。
- 向外部 MCP 授予删除项目、数据或模型的能力。
- 允许外部工具提交任意训练镜像、脚本或 Shell 命令。
- 改变 Runner 出站领取任务、数据不离开用户环境或统一训练环境发行边界。
