# 统一训练环境发行与分发

状态：第一阶段实施基线

更新日期：2026-08-12

## 1. 要解决的用户动作

用户只需要完成一个动作：连接一台自己控制的电脑。LLMWEB 负责识别能力、取得正确环境、验证可用性并保持连接。用户不需要理解容器、CUDA、MPS、下载代理或训练框架。

CloudMCP 管理的 GitOps 节点与外部用户电脑必须消费同一个训练环境版本和相同内容摘要。两种入口只允许在下载传输和系统服务托管方式上不同，不能形成两套训练环境。

## 2. 统一对象

统一训练环境是一个不可变发行版，不是强行包含所有平台的单个物理镜像。每个发行版由一份带内容摘要并绑定源码 revision 的清单定义：

- 环境版本和清单版本。
- Runner 二进制及 SHA256。
- Linux CPU 容器归档、文件 SHA256、加载后的镜像 ID 和运行镜像名。
- Linux NVIDIA 容器归档及驱动兼容要求。
- Apple Silicon 原生环境包及最低 macOS 要求。
- 固定训练引擎、源码 revision、数据素材和许可证证据。
- 每个变体的支持状态、最低资源和自检命令。

同一版本的任何文件、摘要或选择规则不得被覆盖。需要改变内容时发布新版本。

## 3. 第一阶段范围

第一阶段正式交付 Linux x86_64 CPU 入门训练变体：

- 预构建 `nanoGPT` CPU 容器，节点不再执行 `docker build`。
- 预构建 Linux amd64 Runner。
- 统一训练环境清单。
- 由 LLMWEB 产品域提供的 Artifact Gateway。
- 外部连接命令与 CloudMCP/GitOps 入池共同读取该清单。
- 至少 4 核、8GB 内存和 20GB 可用磁盘的安装前检查。
- 已绑定节点拒绝用另一个配对码静默改绑。
- 下载、摘要验证、`docker load`、镜像 ID 验证和最小运行自检全部通过后，Runner 才注册为可用。

Linux NVIDIA 和 Apple Silicon 在同一清单协议中保留明确变体，但在对应预构建产物和真实硬件验收完成前不得标记为可用，也不得改写现有稳定路径冒充闭环。

## 4. 分发路径

```text
外部用户连接指令 ───────────────┐
                              ▼
                        LLMWEB 产品域
                         安装器 / 清单
                              │
                              ▼
                       Artifact Gateway
                              │
                         SHA256 / 镜像 ID
                              │
                              ▼
                         目标电脑本地缓存

CloudMCP → GitOps Agent ──────┘
```

Artifact Gateway 只允许代理当前发行清单列出的固定文件，不接受任意上游 URL。它必须保留 `Range`、`Content-Range`、`ETag` 和内容长度，以便大文件断点续传。客户端即使通过不同代理或缓存取得文件，也必须验证相同摘要。

首次安装缺少完整且校验通过的产物时不得退回 GitHub、PyPI 或模型站点随机下载。已经校验的本地缓存可以在网关暂时不可用时继续运行已有环境。

## 5. 节点归属

第一阶段一台 Runner 节点同一时间只归属一个 LLMWEB 工作区。环境缓存可以复用，以下内容不得跨工作区复用：

- Runner 设备身份。
- 原始数据与授权预览。
- checkpoint 与模型产物。
- 业务训练日志。
- 用户存储凭证。

安装器发现已有 Runner 身份时，必须使用设备凭证和新配对码向控制面确认两者属于同一工作区；同一工作区可以保留身份、数据与产物完成环境升级，工作区不同则停止并提示正式解除原连接。不得忽略新配对码继续旧身份，也不得静默覆盖旧身份。

节点转移的正式顺序是：确认无运行任务、保留或导出产物、撤销旧设备身份、清除精确身份状态、保留校验通过的共享环境缓存、使用新配对码注册并验证工作区隔离。节点恢复出厂不是常规转移方案。

## 6. 宿主机与环境责任

宿主机负责 Docker、NVIDIA 驱动、Metal、磁盘、文件权限、出站网络和系统服务。训练环境负责训练框架、Python 用户态依赖、固定训练逻辑和自检。

容器不能携带 NVIDIA 内核驱动；Apple MPS 不能以 Linux Docker 镜像交付。因此统一清单必须维护平台兼容矩阵，能力不满足时在大文件下载前失败并给出用户可行动说明。

## 7. 连接状态

内部状态按以下顺序推进：

```text
已取得配对码
→ 正在检查电脑
→ 正在下载训练环境
→ 正在验证训练环境
→ 正在连接
→ 可以训练
```

只有 Runner 身份有效、能力与磁盘满足、产物摘要正确、镜像 ID 正确、最小自检通过、数据和输出目录可读写、Runner 心跳正常时，网页才显示“算力已连接”。

## 8. 任务协议

训练任务引用统一环境版本和后端，而不是由用户或控制面自由拼接镜像：

```json
{
  "environment": {
    "version": "1.0.0",
    "backend": "linux-amd64-cpu"
  }
}
```

Runner 只接受自身安装并验证过的环境版本、固定后端和批准镜像。训练开始后环境版本保持不变；新任务可以使用新的稳定版本，旧版本在回滚期内保留。

## 9. 存储与并发

存储分为三个边界：只读且按摘要复用的环境缓存、严格归属工作区的数据、严格归属实验的训练产物。第一阶段每个 Runner 同时只执行一个任务。

清理环境缓存不得删除仍在使用的镜像或用户产物。成功安装、失败、取消和升级都必须报告安装阶段并只清理本次下载的临时文件。

## 10. 供应链与验收

每个正式发行版必须具备：固定源码 revision、文件 SHA256、镜像 ID、构建来源、SBOM、完整漏洞报告和不可变发布标签。已有修复但发行物尚未采用修复的 High/Critical 漏洞必须阻断发布；暂时没有上游修复的漏洞必须保留在报告中，并在后续发行重新评估，不能静默忽略。

第一阶段闭环要求：

1. CI 从干净源码构建 Runner 和 CPU 镜像归档。
2. 最终归档不包含 Git、缓存、密钥、工作区状态或用户产物。
3. 安装器只通过 LLMWEB 产品域取得安装器、清单和发行物。
4. 干净 Linux 节点不执行镜像构建即可完成安装和自检。
5. CloudMCP/GitOps 与外部连接得到相同版本、SHA256 和镜像 ID。
6. 4 核 8GB CPU 节点完成数据准备、训练前基线、训练、checkpoint 选择、同测试集复测和模型导出。
7. 外部用户只看到“连接电脑”和可行动状态，不看到下载代理或后端差异。
