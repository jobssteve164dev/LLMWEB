# Xiaomi MiMo RL 监控页调研与 LLMWEB 落地

调研对象：[mimo-v2.6 RL](https://mimo.xiaomi.com/rl/#overview)，复核时间为 2026-09-19。

## 代码与网络中可直接确认的事实

- 页面是一个很薄的静态壳：HTML 只挂载 `theme.js`、`format.js`、`charts.js`、`app.js` 和一份 CSS，没有发现 React、Vue、D3 或第三方图表库运行时。
- 图表由 `charts.js` 直接创建 Canvas，通过 `ResizeObserver` 自适应尺寸，并监听指针事件显示精确值；页面用 `IntersectionObserver` 延后初始化未进入视口的图表。
- 页面以 URL hash 提供 `overview`、`metrics`、`about` 和单指标图表的可直接访问状态；偏好的横轴、线性/对数尺度和平滑度保存在 `localStorage`。
- 数据按职责拆分为 `runs`、`status`、`live`、`notices`、`benchmarks`、`tags` 和 `series` JSON 接口。前端用 `fetch(..., { cache: "no-store" })` 取数，状态每 10 秒轮询一次，页面时钟每 500 毫秒刷新。
- 首屏信息层级固定为：运行公告、训练摘要、离线评测、常用指标、最新采样动态、数据组成。指标页再提供标签树、搜索与单指标下钻，而不是把所有数据同时塞进首屏。
- HTML、静态资源和 JSON 响应均带 60 秒公共缓存头；series 请求附带运行版本参数用于失效。响应由 MiFE 边缘服务返回，并设置仅允许同源资源的 CSP。
- 公开响应无法证明后端使用的语言、数据库、训练日志采集器或时序数据库；MiFE 响应头只说明交付层，不能据此推断数据层技术。

## 对 LLMWEB 有价值的产品模式

MiMo 页最值得复用的不是它的原生 JavaScript 技术选型，而是四层监控心智：先回答“任务是否正常”，再回答“关键指标如何变化”，随后给出“刚刚发生了什么”，最后允许用户查看原始数值。它还把横轴和尺度控制放在图表附近，并让每个指标都能下钻。

LLMWEB 保留现有 Next.js、React 和自身既有的 3 秒状态刷新，不引入第二套数据通道。Runner 已从训练日志提取 `loss`、`eval_loss`、`learning_rate`、`epoch` 并随事件上报；新监控面直接消费这些真实事件，展示运行摘要、四项趋势、记录/时间横轴、最新动态及可访问的数据表。没有指标时明确等待训练电脑上报，不展示演示数据。

当前状态接口只返回工作区最近 200 条任务事件，因此本版适合当前训练的实时观察，不等同于长期时序仓库。若以后需要 MiMo 指标页那种任意标签搜索、完整历史和大规模下采样，应先扩展 Runner 指标合同与服务端时序查询，再复用现有页面层；不能由前端猜测或伪造缺失指标。
