# LLMWEB 产品设计

状态：首版立项基线

更新日期：2026-08-12

## 1. 产品定义

LLMWEB 是一个用户自带 GPU 算力的网页训练工作台。用户无需学习不同微调框架的命令行和配置体系，即可从数据准备开始，完成训练、监控、评测、模型选择和导出。

产品对用户的承诺是：

> 在一个网页中连接自己控制的 GPU，完成从数据准备、模型微调、效果评测到模型导出的完整流程，同时让原始训练数据留在自己的环境。

LLMWEB 不是 GPU 租赁市场，不转售算力；不是单个训练框架的参数面板；也不是生产推理托管平台。

## 2. 目标用户

首版服务两类用户：

- 拥有本地或云端 Linux x86_64 NVIDIA GPU，或 Apple Silicon Mac，但不希望通过命令行组织微调流程的个人开发者。
- 需要让产品、数据和领域人员共同准备数据、查看结果的小型 AI 团队。

用户应当理解自己的任务和数据，但不应被要求理解训练框架差异、容器编排方式或底层配置文件。

## 3. 用户要完成的动作

产品一级结构围绕六个动作组织：

1. **项目**：说明模型需要完成什么任务，以及怎样才算成功。
2. **数据**：选择用户环境中的数据，检查、处理、切分并形成可追溯版本。
3. **算力**：连接用户控制的 GPU，确认其是否可以执行当前训练。
4. **训练**：选择面向目标的训练方案，启动并持续查看真实进度。
5. **评测**：用同一测试方案比较基础模型、checkpoint 和历史模型。
6. **模型**：选定可用版本，导出 Adapter、合并权重或目标格式。

账号内可以切换多个彼此独立的项目。免费与付费项目额度由 Passport catalog 统一维护；额度用完时只停止新建，不影响已有项目及其训练结果。

训练框架不是一级入口。首版内部使用 LLaMA-Factory，但用户面对的是统一的训练动作与结果。

## 4. 核心流程

```text
定义任务与成功标准
        ↓
连接 GPU 算力
        ↓
选择并检查本地数据
        ↓
建立基础模型基线
        ↓
创建并运行训练实验
        ↓
使用相同测试集自动复测
        ↓
比较结果、选定模型并导出
```

基础模型基线是正式流程的一部分。没有同一测试集上的训练前后对比，训练任务不能被产品表达为“效果已经提升”。

## 5. 数据工作台

### 5.1 数据入口

首版支持：

- 用户 GPU 主机上的 JSON、JSONL 和 CSV 文件。
- Hugging Face 或 ModelScope 数据集标识，由 Runner 在用户环境直接下载。
- 用户自己的 S3 兼容对象存储。

### 5.2 数据检查

数据检查与处理在 Runner 所在环境执行。网页展示：

- 字段映射和少量授权样本预览。
- 空值、格式错误、重复与近似重复。
- Token 长度分布和截断风险。
- 训练集、验证集、测试集的数量与比例。
- 测试集与训练集的疑似泄漏。
- 数据处理步骤和数据版本。

控制面默认只接收统计信息、处理结果和用户明确授权的预览样本，不接收原始训练数据。

### 5.3 数据版本

每个实验必须绑定不可变的数据版本。数据版本至少记录来源引用、处理步骤、切分方式、内容哈希和创建时间。测试集一旦用于基线评测，不得被后续训练任务读取。

## 6. 算力连接

首版支持能够运行 Docker 的 Linux x86_64 CPU/NVIDIA 主机，以及通过原生 Metal/MPS 执行的 Apple Silicon Mac（包括 M1 Max）。用户通过同一条一次性配对命令连接电脑，系统自动选择、下载并验证对应训练环境，再由 Runner 主动通过出站 HTTPS 连接控制面；用户不需要提供公网 IP、SSH 权限、开放入站端口或理解下载代理与执行后端。

CloudMCP 管理的 GitOps 节点与外部用户电脑使用同一训练环境发行版。两者可以采用不同受控传输方式，但最终环境版本、文件摘要和训练行为必须一致。一台 Runner 节点同一时间只归属一个工作区；转给另一个账号前必须正式解除原连接。

网页只展示用户做决策需要的信息：

- GPU 型号、数量和可用显存。
- 机器在线、空闲、训练中或状态待同步。
- 当前模型和方案能否运行。
- 预计显存、磁盘和训练时间。

驱动版本、容器运行时和训练镜像等诊断信息放在故障详情中，不构成普通用户的主操作心智。

## 7. 训练体验

首版支持文本 SFT 和 LoRA；Linux NVIDIA GPU 额外支持 4 位 QLoRA。Apple Silicon 使用原生 Metal/MPS LoRA，基础模型同样限定为 Qwen2.5 0.5B、1.5B、3B 指令模型的固定版本。用户选择速度与质量偏好，系统根据已连接算力生成可执行方案；专业参数位于高级设置。

训练页面重点展示：

- 当前阶段、训练进度和预计剩余时间。
- 训练损失、验证损失、学习率和吞吐量。
- GPU 使用率、显存和温度。
- checkpoint 的评测结果。
- 暂停、继续和取消。
- 可直接行动的异常说明，例如大量样本被截断、验证损失持续恶化或磁盘空间不足。

网页关闭或控制面短暂不可用时，已被 Runner 接受的训练必须继续执行。连接恢复后，Runner 补传日志、指标和最终状态。

## 8. 评测与模型选择

评测使用相同测试集和推理参数比较：

- 基础模型。
- 当前训练的候选 checkpoint。
- 项目历史最佳模型。

首版评测至少覆盖：

- 任务指标：根据任务使用准确率、F1、Exact Match、格式通过率或语义评分。
- 人工查看：盲化展示候选模型输出及失败样本。
- 运行性能：首 Token 延迟、生成速度、显存和模型大小。

结果页面必须表达具体变化与代价，例如“格式遵循率提升，但推理速度下降”，不能只提供曲线或单一总分。

## 9. 模型产物

首版支持以下目标：

- LoRA Adapter。
- 合并权重。
- Hugging Face 兼容目录。
- GGUF。

产物默认保存在用户 GPU 主机或用户指定的 S3 兼容存储中。平台记录模型版本、来源、指标和产物引用，不默认托管模型文件，也不自动删除用户产物。

## 10. 首版范围

### 10.1 必须交付

- 网页控制面与用户工作区。
- Linux x86_64 NVIDIA Docker Runner 与 Apple Silicon Metal/MPS Runner 的统一配对和状态上报。
- 本地数据检查、转换、切分和版本管理。
- 基础模型基线评测。
- 文本 SFT、LoRA、QLoRA。
- 训练进度、日志、GPU 指标和 checkpoint 管理。
- 基础模型与微调模型对比。
- Adapter、合并权重、Hugging Face 和 GGUF 导出。

### 10.2 不进入首版

- Windows、Intel Mac、AMD 与 Intel GPU。
- 多机训练和 Kubernetes。
- 多租户共享同一 Runner 或 GPU。
- DPO、PPO、GRPO 和多模态训练。
- GPU 采购、转售、计费和调度市场。
- 平台托管生产推理服务。
- 任意脚本、任意命令或任意训练镜像执行。

## 11. 成功标准

首版只有同时满足以下条件才算形成产品闭环：

- 新用户能在网页指引下连接一台符合要求的 GPU 主机。
- 原始数据不进入控制面，也能完成数据检查和授权预览。
- 用户能从一个数据版本创建并完成训练实验。
- 网页断开不导致训练中止，恢复后状态能够追平。
- 系统使用同一测试集给出基础模型和微调模型的可核验对比。
- 用户能选定一个 checkpoint 并在自己的环境得到可用模型产物。

## 12. 体验约束

- 界面以用户动作和结果为主语，不以 Runner、容器、适配器或训练框架为主语。
- 同类训练动作始终保持一套配置与评测心智。
- 默认方案必须能完成训练，高级设置用于主动调整，而不是补齐系统未吸收的复杂度。
- 任何“已提升”“已完成”“可发布”的结论必须绑定真实评测或产物证据。

## 13. API 连接

Pro 用户可以在工作台设置中为自己的账户创建 API 连接，把项目、算力和训练能力接到自己选择的调用服务；免费用户不开放 API 设置。API 与网页必须使用同一个用户工作区、项目配额和业务规则；产品不得为任何调用服务建立用户不可见的内部账户、独立工作区或管理员直连入口。

设置页使用面向用户动作的连接卡片展示名称、用途、允许动作、最近使用时间、凭证轮换和撤销。用户不需要理解 CloudMCP、GitOps、Provider Bridge 或其他内部平台；撤销连接不会删除已有项目、训练记录、Runner 或模型，也不会默认取消已经执行的训练。

完整用户 API、CloudMCP 连接器、GitOps Runner 连接器、迁移和验收边界见 [用户训练 API 与内部连接器](../architecture/user-api-and-internal-connectors.md)。
